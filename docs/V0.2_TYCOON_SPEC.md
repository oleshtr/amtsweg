# AMTSWEG V0.2 — Tycoon Core Loop Specification

## Ziel

V0.2 baut den bestehenden ersten AMTSWEG-Loop zu einem langsameren, sichtbaren Idle-/Tycoon-System um.

Leitprinzip:

**manuell arbeiten → Unterstützer gewinnen → Wahlkampfkasse entsteht → Automatisierung verdienen → Stationen leveln → Bottlenecks verbessern → Welt wächst sichtbar → Kommunalwahl**

Das Vorbild ist das strukturelle Game-Feel klassischer Idle-/Mining-Tycoons, nicht deren konkrete Grafik oder Assets.

## Nicht-Ziele

V0.2 führt ausdrücklich NICHT ein:

- reale Parteien oder Politiker
- Ideologien
- Landtag/Bundestag
- Koalitionen
- Medienmanagement
- Prestige
- Skill Trees
- mehrere sichtbare Währungen
- Backend, Accounts oder Cloud Saves
- Werbung oder künstliche Paywall-Timer

## Ressourcen

Spielerseitig bleiben nur zwei Hauptressourcen sichtbar:

1. **Unterstützer**
2. **Wahlkampfkasse (€)**

Interne Durchsatzwerte dürfen existieren, sollen aber nicht als zusätzliche Hauptwährungen im HUD erscheinen.

## Phase 0 — Niemand kennt dich

Startzustand:

- Himmel / Straße / kleine Umgebung
- eine Spielfigur
- Unterstützer: 0
- ein Hauptbutton: **FLYER VERTEILEN**

Nicht sichtbar:

- Geld
- Upgrades
- Helfer
- Infostand
- Ortsbüro
- Untergrund-/Arbeitsbereiche
- Rathaus
- Wahlfortschritt

### Manuelle Flyer-Aktion

Ein Klick startet einen sichtbaren Zyklus von ca. **1,5–2,0 Sekunden**:

1. Passant nähert sich
2. Figur greift Flyer
3. Flyer wird übergeben
4. Passant reagiert
5. Unterstützer steigt
6. Aktion wird wieder verfügbar

Kein Click-Spam.

Ziel: ca. **30–40 manuelle Kontakte pro Minute** bei aktivem Spielen.

## Phase 1 — Wahlkampfkasse

Zielzeit: **ca. 1,5–2 Minuten**

Erster Unlock bei ungefähr **50 Unterstützern**.

Dann erscheinen:

- Wahlkampfkasse im HUD
- kleine Spendendose / Spendenpunkt in der Welt

Es gibt **keinen "Spende sammeln"-Button**.

Geld entsteht automatisch als Folge der Unterstützerbasis.

Erster Richtwert:

```
cashPerSecond = 0.06 + supporters * 0.0015
```

Beispiele:

- 50 Unterstützer → ca. 0,135 €/s
- 100 → ca. 0,210 €/s
- 200 → ca. 0,360 €/s
- 400 → ca. 0,660 €/s

Diese Werte sind Startwerte für Balancing, keine unveränderlichen Wahrheiten.

Animation: gelegentlich wirft ein Unterstützer sichtbar eine Münze in die Spendendose.

## Phase 2 — Helferteam

Zielzeit erster Helfer: **ca. 5–7 Minuten**

Erster Helfer kostet als Startwert ungefähr **35 €**.

Beim Kauf:

- erster Helfer erscheint sichtbar
- erste zusätzliche Arbeits-/Tycoon-Ebene wird aufgedeckt
- Helfer verteilt automatisch Flyer
- aktive Flyer-Aktion bleibt weiterhin möglich

Startleistung Helfer:

```
0.25 Unterstützer / Sekunde
≈ 15 Unterstützer / Minute
```

### Helfer-Level

Station erhält ein eigenes Level.

Upgrade-Kosten als Ausgangspunkt:

```
helperUpgradeCost(level) = 12 * 1.32^level
```

Milestones:

- LV 1: 1 Helfer
- LV 5: sichtbarer Speed-/Produktionssprung
- LV 10: zweiter sichtbarer Helfer
- LV 20: sichtbar besserer Arbeitsplatz / mehr Material

Level-Up muss Zahlen UND Szene verändern.

## Phase 3 — Infostand

Zielzeit: **ca. 12–16 Minuten**

Beispielvoraussetzungen:

- Helferteam mindestens LV 5
- mindestens ca. 150 Unterstützer
- Baukosten ca. 100–120 €

Beim Kauf:

- kurze Aufbauanimation
- Infostand erscheint physisch in der Welt
- zweite Arbeits-/Tycoon-Ebene wird sichtbar
- mehr Passanteninteraktion

Infostand soll nicht nur stumpf +X/s geben.

Er verstärkt die bestehende Kette, z. B.:

```
supporterOutputMultiplier = 1.30
```

## Bottleneck-Prinzip

AMTSWEG soll wie ein Tycoon funktionieren:

- Helfer erzeugen Kontakte
- Infostand kann nur begrenzt Kontakte verarbeiten
- Fundraising kann nur begrenzt Unterstützer monetarisieren

Beispiel:

```
Helfer:      40 Kontakte/min
Infostand:   30 Kontakte/min
```

Dann ist der Infostand der Bottleneck.

Der Spieler soll das auch visuell erkennen:

- Flyer stapeln sich
- Passanten warten
- Helfer stehen kurz herum
- Arbeitsbereich wirkt überlastet

Nach Upgrade löst sich der sichtbare Stau.

"Kontakte" sind eine interne Produktionsgröße, keine neue HUD-Währung.

## Phase 4 — Ortsbüro

Zielzeit: **ca. 24–28 Minuten**

Beispielvoraussetzungen:

- Infostand mindestens LV 10
- ca. 350 Unterstützer
- Kosten ca. 300–400 €

Beim Kauf:

- Gebäude erscheint sichtbar
- Schild / Tür / Arbeitsplatz werden aufgebaut
- dritte Arbeits-/Tycoon-Ebene erscheint
- Mitarbeiter wird sichtbar

Das Ortsbüro verbessert vor allem Fundraising.

Startidee:

```
fundraisingMultiplier = 1.8
```

Beispiel-Milestones:

- LV 1: ein Mitarbeiter
- LV 5: zweiter Arbeitsplatz
- LV 10: zweiter Mitarbeiter + sichtbarer Ausbau
- LV 20: größere Kampagnenzentrale

## Phase 5 — Kommunalwahl wird sichtbar

Zielzeit: **ca. 32–36 Minuten**

Rathaus und Wahlfortschritt bleiben vorher vollständig verborgen.

Beispielvoraussetzungen:

- Ortsbüro vorhanden
- Ortsbüro mindestens LV 5 oder vergleichbarer Fortschritt
- ca. 600–700 Unterstützer

Dann:

- Welt erweitert sich sichtbar
- Rathaus erscheint
- "Nächstes Ziel: Kommunalwahl"
- Wahlfortschritt erscheint erst jetzt

## Phase 6 — Erste Kommunalwahl

Zielzeit vollständige erste Session:

**ca. 40–45 Minuten aktives Spielen**

Victory:

- klarer Kapitelabschluss
- kurze, dezente Celebration
- keine neue Welt / kein neues Kapitel automatisch implementieren

## Pace

Zielkorridor:

- Wahlkampfkasse: 1,5–2 Min.
- erster Helfer: 5–7 Min.
- Helfer LV5: 9–11 Min.
- Infostand: 12–16 Min.
- Infostand LV10: 20–24 Min.
- Ortsbüro: 24–28 Min.
- Wahl sichtbar: 32–36 Min.
- Kommunalwahl: 40–45 Min.

Wichtig:

**Langsam bedeutet nicht langweilig.**

Alle ca. 30–90 Sekunden sollte eine kleine sinnvolle Verbesserung oder Entscheidung erreichbar sein.

## UI-Grundsatz

Die Welt ist das Interface.

HUD oben möglichst nur:

```
AMTSWEG     ★ Unterstützer     € Wahlkampfkasse
```

Große Upgrade-Karten unterhalb der Welt sollen stark reduziert bzw. entfernt werden.

Stationen bekommen Upgrade-Steuerung direkt an der Station, etwa:

```
HELFERTEAM
LV. 8
7,2 Kontakte/min
↑ 34 €
```

## Animationen

Animationen müssen Produktion erklären.

### Manuell
Figur → Passant → Flyer → Reaktion → Unterstützer.

### Helfer
Material holen → laufen → verteilen → zurückkehren.

### Spenden
Unterstützer → Münze → Spendendose/Büro.

### Infostand
Passant → kurze Interaktion → weiter.

### Bottleneck
Warteschlangen / Materialstapel / Leerlauf sichtbar machen.

### Upgrade
Station erhält sichtbares Detail.

### Milestone
zusätzliche Figur / Möbel / Schild / Arbeitsfläche.

Weniger zufällige Floating-Texte; mehr sichtbare Arbeit.

## Active vs. Idle

Aktives Spielen soll schneller sein, aber nicht zwingend.

Aktiv:

- manuelle Flyer-Aktion
- Upgrade-Entscheidungen
- Bottlenecks lösen

Idle:

- Helfer arbeiten
- Unterstützer steigen
- Spenden entstehen

Offline-Ertrag erst nach erster Automatisierung.

Optional für V0.2:

- maximal 2 Stunden Offline-Ertrag
- einfache Rückkehr-Zusammenfassung

## Architektur

Bestehende einfache Architektur beibehalten:

- HTML
- CSS
- Vanilla JavaScript
- localStorage

Keine Framework-Migration.

Zentrale CONFIG für:

- Aktionsdauer
- Unlocks
- Kostenkurven
- Produktionsraten
- Multiplikatoren
- Milestones
- Offline-Cap
- Wahlbedingungen

Keine Gameplay-Magic-Numbers in UI-Code oder CSS.

## Akzeptanzkriterien

1. Frischer Spielstand zeigt nur Stage 0.
2. Geld ist am Start unsichtbar.
3. Kein manueller Spenden-Button existiert.
4. Flyer-Aktion hat eine echte Zyklusdauer und kann nicht gespammt werden.
5. Wahlkampfkasse entsteht automatisch durch Unterstützer.
6. Helfer ist der erste Automatisierungsmoment.
7. Stationen können gelevelt werden.
8. Level-Milestones verändern die Welt sichtbar.
9. Große Upgrade-Karten werden durch station-nahe Controls ersetzt.
10. Infostand und Ortsbüro können nicht übersprungen werden.
11. Rathaus/Wahlfortschritt erscheinen erst spät.
12. Zielzeit bis Wahl liegt ungefähr bei 40–45 Minuten aktivem Spiel.
13. Keine längere tote Phase ohne sinnvolle Entscheidung.
14. Save/Reload erhält Progression korrekt.
15. Keine Console/Page Errors.
16. Desktop und Mobile bleiben bedienbar.
